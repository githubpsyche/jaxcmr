Slurm cluster setup with VS Code

Prepare a remote workspace for JAXCMR and run a notebook on resources allocated by Slurm. You do not need to understand JAXCMR’s models or have Python installed on your own computer.

A cluster is a collection of shared computers. It can provide more memory and processors and run independent jobs simultaneously. This guide establishes an interactive workspace; long-running work that continues after disconnecting uses separately submitted batch jobs. Requesting more CPUs does not automatically make a calculation faster.

Where the work happens

Location Role
Your computer Displays VS Code and connects to the cluster
Login node Provides access to files and lets you prepare and submit work
Compute node Runs calculations using resources allocated by Slurm

A node is a computer in the cluster. Login nodes are shared access points, so substantial calculations belong on compute nodes. Slurm manages access: you request resources, and it starts your work when suitable resources are available.

Before you begin

You need a cluster account and the following details from your institution:

Information What you need it for
Login address and username Connecting to the cluster
Authentication requirements Any VPN, password, authentication app, or SSH key needed to sign in
Project storage location Keeping code, installed software, and results
Slurm account Selecting the research allocation charged for computing use
CPU partition Selecting a permitted group of compute nodes
Supported VS Code access method Connecting the editor to allocated resources

Your login username and Slurm account may differ. Choose storage accessible from both login and compute nodes, suitable for Python environments. Check its backup and automatic-deletion policies.

Prefer your institution’s managed VS Code service if it provides one. Use its connection and allocation instructions, then follow the project, environment, and notebook steps below in that workspace.

The SSH route below requires your institution to support all three of these:

  • VS Code and software installation on the login node.
  • SSH access through the login node to a compute node assigned to you, including any required key setup.
  • Running the connected VS Code processes inside your Slurm allocation. A matching computer name alone does not establish this; the cluster must support this connection method.

These are cluster settings to confirm before starting. For example, Harvard documents distinct SSH and tunnel routes. If direct SSH is unsupported, use the institution’s managed service or documented tunnel procedure.

1. Connect VS Code to the login node

On your computer, install VS Code. On macOS, move it into Applications; on Windows, run the installer. SSH creates an encrypted connection to another computer; see VS Code’s SSH client instructions if it is not installed.

  1. Choose View → Extensions and install Remote - SSH, published by Microsoft.
  2. Open View → Command Palette, which searches VS Code’s commands, and select Remote-SSH: Add New SSH Host….
  3. Enter the following command with your username and login address, then choose the configuration file in your user folder to save it:
ssh YOUR_USERNAME@LOGIN_HOST

Replace both capitalized values; @ separates your username from the computer’s address. Use your institution’s connection command if it differs. From the Command Palette, choose Remote-SSH: Connect to Host… and select the saved host.

Complete sign-in, checking any first-connection host fingerprint against your institution’s published information. Select Linux if asked for the remote operating system. The new window’s lower-left indicator should show SSH: and the login host. See VS Code’s connection instructions.

In this window, Explorer, saved edits, and new terminals use the cluster. A local project copy remains separate; Remote-SSH does not synchronize it automatically.

Use this window to prepare the project and request resources.

2. Open your project on the cluster

Choose File → Open Folder and open your approved project storage location. Choose Terminal → New Terminal. A terminal accepts commands; enter each command below and press Return or Enter:

pwd
git clone https://github.com/githubpsyche/jaxcmr.git
cd jaxcmr
pwd
  • pwd prints the current folder, where commands look for relative filenames.
  • git clone downloads JAXCMR’s code and examples into a new jaxcmr folder.
  • cd jaxcmr moves the terminal into it; the final pwd prints its full location.

Use File → Open Folder to open that full location. Confirm that you trust this project if prompted. Explorer should show guide, templates, pyproject.toml, and uv.lock. If you already have a checkout on the cluster, open it instead of cloning again.

NoteIf Git or uv is unavailable

Some clusters provide software through environment modules. A command such as module load NAME selects an administrator-installed package and adjusts the current terminal so it can find that software. Replace NAME with your institution’s actual module name and version. This selects existing software; uv installs Python packages for your project. Record any required module commands, since new sessions and jobs may need them again. If Git and uv are already available, no extra module is needed. See the Environment Modules documentation.

3. Install Python and JAXCMR

Open a new terminal in the remote jaxcmr folder. Python runs the calculations; uv installs Python and the packages the project needs. Check for uv with:

uv --version

If your institution provides uv, use that installation. Otherwise, where user installations are permitted, run:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"

The first command downloads and runs uv’s installer. For its default installation location, the second makes uv available in this terminal: $HOME is your cluster home folder, and source applies settings from the named file. If downloads are restricted, use your institution’s supported installation route.

Install the project:

uv sync --locked

This installs Python 3.12 if needed, JAXCMR, and notebook tools into .venv, the project’s environment folder. Notebooks in this project can use this same installed software. --locked uses the repository’s recorded package versions. Wait for installation to finish successfully. See uv’s environment documentation.

Create this environment on the cluster even if you have a local installation; copying your computer’s environment does not make it portable.

4. Request computing resources

An interactive allocation gives you temporary resources for commands entered in a terminal. Use your institution’s interactive-access command if it provides one. Otherwise, this is a standard Slurm example, run from the login node with jaxcmr as the current folder:

srun \
  --account=YOUR_ACCOUNT \
  --partition=YOUR_CPU_PARTITION \
  --nodes=1 \
  --ntasks=1 \
  --cpus-per-task=1 \
  --mem=4G \
  --time=00:30:00 \
  --pty bash

Replace the account and partition. Each backslash continues the same command onto the next line.

Part Meaning
srun Requests resources and starts a program
--account Selects the project allocation
--partition Selects the group of machines
--nodes=1 Uses one compute node
--ntasks=1 Starts one task
--cpus-per-task=1 Allocates one CPU to that task
--mem=4G Requests 4 GB of memory
--time=00:30:00 Limits the session to thirty minutes after it starts
--pty bash Opens an interactive command shell on the allocated node

These values suit a small setup check; adapt them to your cluster’s permitted requests and required options. You may wait for resources. See Slurm’s srun documentation.

Once the session starts, run:

hostname
echo "$SLURM_JOB_ID"

Record the computer name and job number: hostname identifies the allocated node; echo prints the job number stored in SLURM_JOB_ID. Keep this terminal and its VS Code window open. They hold the allocation while you connect a second window to the node.

Only this terminal has moved to the compute node. The original VS Code window and its notebook kernels still belong to the login node.

5. Connect a second window to the compute node

For a managed VS Code service, use its allocated workspace and continue to step 6. For the supported SSH route:

  1. Choose File → New Window to open a local VS Code window. Keep the allocation window open.
  2. In the new window, choose Remote-SSH: Open SSH Configuration File… from the Command Palette. Select the local configuration file used in step 1.
  3. Add this entry before any general Host * entry, replacing the capitalized values. COMPUTE_HOST is the allocated node’s SSH address, usually the name printed above. LOGIN_HOST is the login address or configured alias from step 1.
Host jaxcmr-compute
    HostName COMPUTE_HOST
    User YOUR_USERNAME
    ProxyJump YOUR_USERNAME@LOGIN_HOST

jaxcmr-compute is a convenient connection name. HostName selects the computer, User selects your account, and ProxyJump routes the connection through the login host. Keep any additional authentication settings your institution requires.

Save the file, then use Remote-SSH: Connect to Host… → jaxcmr-compute in this new window. After authentication, its lower-left indicator should show SSH: jaxcmr-compute. Open a new terminal and run hostname; it must match the allocated node, not the login node.

Use File → Open Folder to open the same full jaxcmr path on shared storage. The files are already there. This second window is now your working window for notebooks.

6. Select the environment and check your setup

A Jupyter notebook is an .ipynb file combining explanations, Python code, and results. Its sections are called cells; code cells run in a Python process called a kernel. VS Code’s Jupyter extension supplies the notebook controls.

In the compute window:

  1. Open View → Extensions and install Microsoft’s Python and Jupyter extensions for SSH: jaxcmr-compute. Use your institution’s supplied extensions if installation is restricted.
  2. In Explorer, open guide/examples/first-simulation.ipynb.
  3. Choose Select Kernel → Select Another Kernel → Python Environments and select Python 3.12 from this project’s .venv. If a kernel is already selected, click its name to change it.
  4. Click Run All. The Colab installation cell skips installation here. Wait for all cells to finish; the first calculation may take longer while JAX prepares it.

Choosing Python Environments in the compute window selects Python on that computer. Selecting an environment in the original login window would run there instead. See VS Code’s kernel guidance.

The final cell should print study and recall sequences, confirming that JAXCMR can run in the selected environment. Saved output can be visible before execution, so check that this run finishes without errors. The notebook explains the simulation itself.

Finish and return later

Save the notebook with File → Save, then close the compute connection. In the original allocation terminal, run:

exit

This ends the interactive job and returns that terminal to the login node. Run squeue --jobs=YOUR_JOB_ID, replacing the placeholder with the recorded job number, to check that it has ended. If it remains queued or running, scancel YOUR_JOB_ID cancels that allocation. Closing only the editor window is not a substitute for ending the job.

Your files and .venv remain on shared storage, subject to its retention policy. Live Python state disappears when the kernel ends. To return, reconnect to the login host, request a new allocation, update HostName in the existing jaxcmr-compute entry, and reconnect the compute window. Open the project, select its environment, and run your notebook from the beginning. Load any site-required modules as part of the supported connection procedure.

Continue with the tutorials

In an allocated compute window, open guide/tutorials/data-preparation.ipynb for Preparing data for JAXCMR and select the same .venv environment. You can use this workspace for other project notebooks while the allocation remains active. Choose resources appropriate to their work; this setup request is only for a small check.

If something goes wrong

NoteSSH or VS Code cannot connect

From a local VS Code window, open Terminal → New Terminal and try ssh YOUR_USERNAME@LOGIN_HOST. If ssh is missing, follow the SSH client instructions in step 1. If sign-in fails, check the login address, VPN, and authentication requirements. After a successful terminal test, exit returns to your computer. If SSH works but VS Code does not, inspect View → Output → Remote - SSH.

For the compute connection, confirm that the allocation is still running, HostName names its node, and your institution supports SSH through the login host with your authentication setup. Use its managed service or tunnel procedure where direct SSH is unsupported.

NoteA command is not found

Check which machine the terminal belongs to. On the cluster, confirm that installation completed and load any required software module. For a default uv installation, source "$HOME/.local/bin/env" makes it available in the current terminal.

NoteSlurm rejects the request

Check the account, partition, and permitted resource settings against your allocation. These are cluster access settings, not Python settings.

NoteThe compute node cannot find the project or import JAXCMR

Check pwd, shared storage access, and whether installation finished successfully. Use .venv/bin/python from the intended project folder.

When asking for help, include the command, complete error message, and whether it ran on your computer, a login node, or a compute node.
