The probability of stopping depends on which candidates remain available. A model can stop only on exhaustion, use a schedule indexed by recall count, or compare support for available and unavailable studied candidates. Each calculation returns one if retrieval has ended or no candidates remain.

A model with a fixed stopping rule can call the corresponding function directly. Configurable CMR variants use these calculations through the response policy that assigns probabilities to STOP and each item.

Stopping on exhaustion

stop_when_exhausted Stop when retrieval has ended or there are no available candidates.
NoStopTermination Continue until the model becomes inactive or exhausts its available candidates.
SupportsNoStop Availability information needed to stop when retrieval is exhausted.

Stopping by output position

positional_stop_probability Look up the probability of stopping after the given number of recalls.
PositionalTermination Set stopping probability from the number of items recalled so far.
SupportsPositional Availability and recall count needed for positional stopping.

Stopping by support ratio

support_ratio_stop_probability Calculate stopping probability from two totals of retrieval support.
SupportRatioTermination Compare support for available and unavailable studied candidates.
SupportsSupportRatio Candidate information needed by the existing support-ratio rule.

Legacy STOP-candidate scoring

RetrievalDependentTermination Use a dedicated STOP candidate’s independently calculated probability.
SupportsRetrievalDependent Input requirements of the legacy STOP-item policy.

Look up the probability of stopping after the given number of recalls.

Parameters

Returns

PositionalTermination

jaxcmr.components.termination.PositionalTermination(list_length, parameters)

Set stopping probability from the number of items recalled so far.

At recall count r, the probability is stop_probability_scale * exp(r * stop_probability_growth), capped at 1 - FLOAT32_EPS * number_available. The first decision uses r = 0. The schedule ends at r = list_length - 1. Higher counts use its last value. The model supplies is_active, the candidate mask recallable, and the recall count recall_total. Model requirements

Parameters

Name Type Description Default
list_length int Number of positions in the stopping schedule, starting at count zero. required
parameters Parameters stop_probability_scale gives the initial value before the cap. stop_probability_growth controls its change per recall. required

SupportsPositional

jaxcmr.components.termination.SupportsPositional: Protocol

Availability and recall count needed for positional stopping.

In addition to is_active and recallable, the model supplies recall_total, the number of recall events so far.

support_ratio_stop_probability

jaxcmr.components.termination.support_ratio_stop_probability(available_support, unavailable_support, *, scale, growth, is_active, available_count)

Calculate stopping probability from two totals of retrieval support.

Parameters

Name Type Description Default
available_support float Total support for studied candidates that are available for recall. required
unavailable_support float Total support for studied candidates that are unavailable for recall. required
scale float Additive term in scale + exp(-growth * ratio). The ratio is available support divided by unavailable support, or infinity when the latter is zero. required
growth float Coefficient of the support ratio in the exponential. required
is_active bool Whether the trial is still in retrieval. required
available_count int Number of candidates that the model can still recall. required

Returns

Name Type Description
Float[Array, ''] One if retrieval has ended or no candidates remain. Otherwise the result of the support-ratio equation, capped at 1 - FLOAT32_EPS * available_count. The ceiling uses float32 machine epsilon even for float64 probabilities.

SupportRatioTermination

jaxcmr.components.termination.SupportRatioTermination(list_length, parameters)

Compare support for available and unavailable studied candidates.

The model supplies is_active, the masks studied and recallable, and candidate_activations(mask). Both masks and the returned scores refer to the same candidates. The model must be able to score unavailable candidates too. The rule scores each group separately and sums its support.

Recalling an item makes it unavailable when repeated recalls are disabled. When repeats are enabled, a recalled item stays in the available group and contributes to its support. Model requirements

Parameters

Name Type Description Default
list_length int Accepted as part of the stopping-rule constructor interface. required
parameters Parameters stop_probability_scale sets the additive term. stop_probability_growth sets the coefficient of the support ratio. required

SupportsSupportRatio

jaxcmr.components.termination.SupportsSupportRatio: Protocol

Candidate information needed by the existing support-ratio rule.

studied, recallable, and candidate activations must refer to the same candidate space. The rule scores the available and unavailable subsets of studied candidates separately. A recalled item can still belong to the available subset if the model permits repeated recall.

RetrievalDependentTermination

jaxcmr.components.termination.RetrievalDependentTermination(list_length, parameters)

Use a dedicated STOP candidate’s independently calculated probability.

The model supplies is_active and a Boolean recallable mask. It must score outcome_probability(item_count) as STOP without calling this policy. A model that uses item_count for the last study item cannot use this rule.

The rule reads no stopping parameters. While recall can continue, the returned probability is capped at 1 - FLOAT32_EPS * number_available. Model requirements

SupportsRetrievalDependent

jaxcmr.components.termination.SupportsRetrievalDependent: Protocol

Input requirements of the legacy STOP-item policy.

item_count must identify an explicit STOP candidate, and evaluating its outcome probability must not call this termination policy again. Structural typing cannot establish either condition. Ordinary CMR models use item_count as the highest local item code.
