jaxcmr.fitting

Estimate model parameters from a loss evaluated on selected trials.

The loss determines what counts as a good fit. For example, a likelihood loss scores the observed recall sequence, while an SPC loss compares observed and simulated serial position curves. The fitter searches within the free-parameter bounds for values that minimize the chosen loss.

ScipyDE and the Evosax differential-evolution fitters compare populations of candidates. ScipyLBFGSB and ScipyTrustConstr use loss gradients and can search from several starting points. ParameterSpace translates between search coordinates and physical parameter values. Results report parameters in the units used by the model.

A pooled fit estimates one parameter set from all selected trials. Participant-wise fitting estimates a set for each participant. In a FitResult, each row links a parameter set to its objective value and optimizer results. parameters_for_subjects uses those rows to assign a pooled estimate or matching participant estimates for simulation.

EvosaxDE

jaxcmr.fitting.EvosaxDE(dataset, features, base_params, model_factory_cls, loss_fn_cls, hyperparams=None)

Fit trial-index losses with differential evolution and independent restarts.

Each restart uses a fresh population. The serial, scanned and mapped fitters share the same numerical search and random-key schedule. Scanned and mapped participant fitting require equal selected trial counts across participants.

The hyperparams mapping sets bounds, pop_size (a multiplier of the number of free parameters), best_of, num_steps and seed. Optional transforms select ParameterSpace search coordinates; omission preserves physical-coordinate search. No observation preparation is discovered or cached by these fitters.

ScipyLBFGSB

jaxcmr.fitting.ScipyLBFGSB(dataset, features, base_params, model_factory_cls, loss_fn_cls, hyperparams=None)

Fit a differentiable loss with box bounds and reproducible restarts.

The constructor accepts the same dataset, model factory and loss factory as the DE fitters, including configured callable loss constructors. Optimization uses explicit unit-interval coordinates for parameter scaling; the loss always receives physical parameter values. SciPy owns the local optimizer. Only loss evaluation and differentiation use JAX.

Required hyperparameter: bounds (a nonempty name -> [lower, upper] mapping of finite, strictly ordered bounds). Optional controls: transforms (a name -> ‘linear’/‘log’/‘log1p’/‘exp_neg’ mapping), sampling_transforms (same syntax, defaults to transforms), initial_params (one complete physical starting mapping, refined first), best_of (maximum local solves, default 8), screening_size (64), screening_batch_size (16), min_start_distance (0.1), seed (0), num_steps (500), max_fun (15000), relative_tolerance (1e-9), gradient_tolerance (1e-5), max_line_search_steps (30), time_limit_seconds (None), and local_time_limit_seconds (None, an allowance for each restart). These defaults describe L-BFGS-B; the trust-constr subclass documents its solver-specific controls. By default, score a Latin-hypercube bank and refine promising, separated candidates. Distances are RMS differences in those sampling coordinates; optimization uses transforms independently. Set screening_size=0 for unscreened uniform restarts; combine this with best_of=1 and initial_params for local polishing. Transforms are explicit: CMR can use {‘primacy_decay’: ‘exp_neg’} to fit retention while preserving its physical decay parameter and bounds.

Time limits include screening and all restarts and are checked between evaluations. One initial value/gradient is always allowed as a fallback, recorded explicitly if late. Later improvements are retained only when evaluated before both deadlines; in-flight work cannot be interrupted. Call warmup(mask) to measure compilation separately. Without warmup, compilation counts toward the time limits. Nonfinite values/gradients end that restart, with diagnostics retained; a finite objective with an invalid gradient is never reported as a good fit.

Uses the caller’s JAX precision configuration; it never changes global JAX settings. Double precision is recommended for tight tolerances and bounds near singular model limits. The loss must supply meaningful derivatives; differentiability cannot be inferred from the general LossFn protocol.

Caller requirements: counts are positive integers, except screening_size may be zero. min_start_distance lies in [0, 1]; tolerances are finite and nonnegative; supplied time limits, trust radii and barrier parameters are finite and positive. initial_params must name every free parameter once with finite values inside its bounds. L-BFGS-B-only options must not be passed to trust-constr.

ScipyTrustConstr

jaxcmr.fitting.ScipyTrustConstr(dataset, features, base_params, model_factory_cls, loss_fn_cls, hyperparams=None)

Bounded trust-constr with JAX gradients and SciPy’s BFGS curvature.

Accepts the same dataset, model, loss and FitResult contract as ScipyLBFGSB. Required option: bounds. Shared controls include transforms, sampling_transforms, initial_params, screening, seed, restart count, and global/per-restart time limits. Sampling defaults to the optimization coordinates; use an explicit mapping to choose a different distribution.

Defaults: best_of=4, screening_size=64, screening_batch_size=16, min_start_distance=0.1, num_steps=1000, gradient_tolerance=1e-7, step_tolerance=1e-12, barrier_tolerance=1e-10, initial_trust_radius=1.0, initial_barrier_parameter=0.1. L-BFGS-B’s max_fun, relative_tolerance and max_line_search_steps controls are not accepted. No Hessian is differentiated or compiled: SciPy updates its curvature estimate from the gradients.

Call warmup(mask) before imposing short fitting budgets. Deadlines include screening and restarts and are checked between evaluations. One initial evaluation is guaranteed as a fallback; any late fallback is identified in diagnostics. Successful solver termination is not proof of a global optimum.

ParameterSpace

jaxcmr.fitting.ParameterSpace(bounds, transforms=None)

Map bounded model parameters to unit-interval optimization coordinates.

bounds and all model-facing values use physical parameter units. Selected parameters may use log, log1p, or exp(-decay) coordinates before their transformed interval is scaled to [0, 1]. This changes the geometry of optimization and uniform sampling, not the model family.

Conversion methods use the last array axis for parameters, in names order, and preserve all leading dimensions. They support JIT, vmap and differentiation using the caller’s JAX precision. Construction rejects bounds whose intervals or transforms collapse at that precision; decay bounds up to 100, for example, require x64 for retention coordinates.

Attributes

Name Type Description
names Parameter names in the insertion order of the bounds mapping.
bounds Original physical bounds, shaped (parameters, 2).
transforms dict[str, ParameterTransform] Explicit transform choices; omitted names use linear scaling.
lower Representable physical lower bounds, rounded inward if necessary.
upper Representable physical upper bounds, rounded inward if necessary.

select_starts

jaxcmr.fitting.select_starts(candidates, scores, count, min_distance=0.1)

Choose low-loss candidates separated in sampling coordinates.

Stable score ordering resolves ties in input order. Separation is the root mean square coordinate difference; it discourages redundant starts without claiming to identify distinct attraction basins.

Parameters

Returns

Example::

combined = combine_participant_parameters([
    {"subject": [2], "rate": [0.4], "enabled": [True]},
    {"subject": [1], "rate": [0.2], "enabled": [False]},
])
assert combined["subject"] == [1, 2]
assert combined["enabled"] == [False, True]

parameters_for_subjects

jaxcmr.fitting.parameters_for_subjects(record, subject_ids)

Assign fitted parameter rows to requested participants, preserving order.

A pooled record (pooled=True, or a sole subject ID of -1 in older records) supplies one parameter set to every requested participant. Other records are matched by subject identity; unused fitted rows are allowed. This prepares inputs to simulate_dataset without loading data, constructing models, or checking the scientific compatibility of a fit and experiment.

Parameters

Name Type Description Default
record Mapping[str, Any] A fit record with nonempty, aligned one-dimensional fits columns, including integer subject IDs. Participant rows must have distinct IDs covering the requested participants. A pooled declaration must describe exactly one row with ID -1. Optional fit_configuration.parameters.fixed takes precedence over fixed when restoring Boolean parameter types; each Boolean parameter named there must have a corresponding fits column. required
subject_ids Sequence[int] | Integer[Array | np.ndarray, ' participants'] Nonempty sequence or vector of distinct integer IDs. Floating-point IDs, Boolean IDs and the pooled sentinel -1 are excluded. These and the record requirements are caller preconditions, not runtime checks. required

Returns

Name Type Description
dict[str, Real[Array, ' participants'] | Bool[Array, ' participants']] A new mapping of one-dimensional JAX arrays in the requested order, including subject. Inputs remain unchanged. Runs outside JIT.

Example::

parameters = parameters_for_subjects(saved_fit, [12, 5])
# Every parameter column now corresponds to participant 12, then 5.
