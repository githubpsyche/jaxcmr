Evaluation uses datasets, parameter values and fit records already produced by the library. There is no single evaluation protocol: each comparison requires the representation and assumptions of the helper being used.

12.1 Which objects answer which questions?

Question Library inputs and operations Complete procedure
Does the model reproduce a behavioral pattern? Observed and simulated RecallDataset objects passed to the same analysis and plotting functions, such as plot_spc(). Simulation
What changes when a parameter changes? Shared study inputs, a fixed model configuration and deliberate parameter interventions followed by simulation and analysis. Parameter exploration
How do likelihood fits compare? Compatible named fit records passed to comparison helpers in jaxcmr.summarize. Model comparison

A behavioral match, an intervention and a likelihood comparison answer different questions. In particular, forced agreement with the observed recall length is not evidence that a model predicts when recall stops.

12.2 Fit-record conventions at the comparison boundary

FitResult provides parameter roles, objective values and row identifiers. Comparison helpers additionally use a name. The templates record the data selection, model configuration and objective needed to establish comparability.

Before comparing likelihood scores, establish that the records concern the same observations, included events and likelihood definition. Check whether parameters were pooled or independently fitted and how many values were estimated. A lower discrepancy loss cannot be substituted for NLL merely because both appear in a field named fitness.

The supplied source-only and broader eCMR records are pooled fits to the same all-condition selection with the same termination-excluded objective and stopping policy. Their emotional modulation differs in whether it also acts on temporal context. Each has ten free parameters and one pooled fit row.

These examples were refitted under the current library. Both learn before context updating, fix emotional encoding drift at 1 and tie emotional recall drift to temporal recall drift. They omit the legacy emotion_drift_rate. Historical fits also require their original context equations and parameter interpretations; a shared import path alone does not identify that behavior.

12.3 Compare summed negative log likelihoods

jaxcmr.summarize.calculate_aic() accepts records containing name, free and fitness, and returns a DataFrame sorted by AIC. Each fitness entry must be a summed negative log likelihood for one fitted parameter set:

\[\mathrm{AIC} = 2k + 2\,\mathrm{NLL}.\]

These saved fits already contain NLL and can be supplied directly. A pooled fit incurs one parameter penalty. Independently fitted participant rows incur one penalty each, and their identifiers must match across models.

Calculate AIC directly from the saved NLL records 
from jaxcmr.summarize import calculate_aic

calculate_aic(records)
Model AIC
1 Broader eCMR 14348.715746
0 Source-only eCMR 14358.852540

The new source-only and broader fits have NLLs 7169.426 and 7164.358, respectively. Their AIC difference is 10.137, favoring broader eCMR. The within-model differences between the two three-restart seed sets are 0.005 and 0.049 NLL units. The ranking is the same in both seed sets.

The result is a library-produced table. Lower AIC is preferred within this comparison; it does not establish a unique explanation of the experiment. Each model contributes one pooled parameter set, so len(free) is the parameter count for that row. calculate_aic_weights() uses the same NLL convention and parameter penalties as calculate_aic().

Participant-wise comparisons align rows by subject identifier and require finite scores for the same participant set. A pooled row is not a sample of independent participant estimates. Mean-difference helpers return the mean and interval half-width; median-difference helpers return the median and the actual bootstrap lower and upper endpoints.

calculate_bic_scores(results, n_obs) and the AICc helpers require positive observation counts for each fitted parameter row. Counts follow the first record’s original participant order; the library aligns them with the scores. Specify the scientific counting unit and selection explicitly. A scalar count is valid only for one fitted row; AICc requires each count to exceed k + 1.

floor_nested_fitness(raw_results, nesting_pairs) returns separate comparison records and an adjustment table without changing the raw fits. Label adjusted scores and save the adjustment table beside them. Keep raw fits for parameter summaries, simulations and held-out evaluation: an adjusted score is not a newly optimized parameter set. The helper trusts the declared nesting relationships.

Bayesian model selection uses an AIC/AICc-based evidence approximation over participant fits. A pooled row cannot supply participant-level inference; failure to converge raises an error rather than returning a result.

12.4 Experimental cross-validation functionality

jaxcmr.experimental.cross_validation contains an experimental driver, with CVResult describing fold-specific fits, participant identifiers, training scores and held-out scores. The current driver mixes pooled fitting with participant-level scoring and can return incorrect held-out scores; it is not ready for scientific use. A held-out comparison requires an appropriate split, fitting only the training observations and evaluating the held-out observations under the chosen objective. It is a different procedure from comparing in-sample AIC values.

See Fitting Procedures for result structure and the model comparison template for the full pooled comparison. These interfaces organize the evidence; selecting a scientifically meaningful comparison remains part of the research design.
