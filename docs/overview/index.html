Library Guide

This guide explains JAXCMR’s data structures, interfaces and conventions: what each part receives, what it returns and where another part uses it. It also identifies entry points for supplying compatible functions or implementations. The Templates assemble these parts into complete research procedures.

How the interfaces connect

A model factory creates a model for an experiment and parameter values. Likelihood calculations follow recorded responses through that model; simulation samples new responses. Both observed and simulated datasets can enter recall analyses. A compatible analysis callback can also supply the summary used by a behavioral objective. Fitters search parameter values using a loss and return records for subsequent simulation and evaluation.

Simulation can use hand-chosen parameters without a fit. Analysis can describe observations without a model. These are connected interfaces, not a mandatory sequence of steps.

What a protocol provides

A Python Protocol describes the attributes and methods a consumer expects. A compatible implementation need not inherit from that protocol. For a callable protocol such as RecallAnalysisFn, an ordinary function with the specified arguments and behavior can be passed directly to its consumer. The analysis callback example shows this connection using an existing SPC calculation.

Signatures alone are not enough: array dimensions, item coding, parameter order and JAX-compatible operations also determine whether implementations work together. Each topic explains these responsibilities alongside the relevant declaration. Examples illustrate one connection at a time.

RecallDataset and FitResult are dictionary types, not protocols. They describe fields and alignment, without being comprehensive runtime validators. Other conventions, such as template-added provenance or objective signs expected by comparison helpers, are established by the procedures that produce and consume the records.

Configuring a reusable procedure

Template notebooks separate literal settings from the Python objects constructed from them:

  1. A tagged parameters cell holds paths, selections, parameter values, import names and output locations. Parameterized execution can replace these literals for another run.
  2. Setup imports implementations and constructs factories, masks and other derived objects from those settings.
  3. The procedure produces outputs and retains the effective settings.

Independent executions need separate output locations. Changes to fit parameters or simulation settings require corresponding new simulation outputs. The Templates explain parameterized execution and provide complete procedures; this guide describes the structures they connect.

Using the illustrations

The topic notebooks retain small executed examples using the existing war-photo-recall observations and supplied fits. Their protocol declarations are visible; expand a labeled code block to inspect an executable example. To rerun one, use Download notebook and place it beside the shared data/ folder from the Templates downloads. The homepage gives the installation command.
