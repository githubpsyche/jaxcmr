10  Fitting Procedures

  • Show All Code
  • Hide All Code

Fitters search parameter values by repeatedly evaluating a loss. The FittingAlgorithm protocol separates that search from the model factory and objective, and FitResult describes the returned record.

10.1 The fitting interface

Declaration from jaxcmr.typing:

class FittingAlgorithm(Protocol):
    def __init__(
        self,
        dataset: RecallDataset,
        features: Float[Array, "word_pool_items features_count"] | None,
        base_params: Mapping[str, Float_],
        model_factory_cls: type[MemorySearchModelFactory],
        loss_fn_cls: type[LossFn],
        hyperparams: dict[str, Any] | None = None,
    ): ...

    def fit(
        self, trial_mask: Bool[Array, " trials"], subject_id: int = -1
    ) -> FitResult: ...

    def fit_subjects(self, trial_mask: Bool[Array, " trials"]) -> FitResult: ...

Existing implementations include ScipyDE and EvosaxDE in jaxcmr.fitting. Both take a model factory class and a loss class. These arguments are the entry points for changing the modeled process or fitting objective without rewriting the optimization procedure. A compatible alternative fitter supplies the same constructor and fitting methods; optimizer-specific controls remain in its hyperparams mapping.

Configuration Meaning
model_factory_cls Builds the models used by the loss. Component choices belong to this configuration.
loss_fn_cls Defines the objective minimized by the search.
base_params Fixed model values and defaults overridden by free parameters.
hyperparams['bounds'] Names of free parameters with lower and upper bounds in model units.
Other hyperparams Search controls such as generations, population size, stopping tolerances and seed.

Bounds define the free parameter order passed through the loss adapter. Supported parameter transformations can change the search coordinates; losses and returned fit values still use physical model units.

10.2 Pooling and participant fits

fit(trial_mask) estimates one parameter set for all selected trials. Its default result label is subject_id=-1, the pooled-fit convention. subject_id labels the result; it does not itself select that participant’s trials. fit_subjects(trial_mask) performs separate fits using the dataset’s participant identifiers and the supplied selection.

A mask selects observations. Pooling specifies which observations share parameters. Neither choice is determined by the optimizer. Changing from pooled to participant fits changes the statistical model and the available information per parameter set.

10.3 The returned record

Declaration from jaxcmr.typing:

class FitResult(TypedDict):
    fixed: dict[str, float]
    free: dict[str, list[float]]
    fitness: list[float]
    nit: list[int]
    converged: list[bool]
    fits: dict[str, list[float]]
    hyperparameters: dict[str, Any]
    fit_time: float
    diagnostics: NotRequired[dict[str, Any]]

Entries at the same index in fitness, nit, converged and every fits array refer to the same fit row. fits['subject'] identifies that row; identifiers are labels, not positional indices. fits includes fixed and fitted parameter values, while fixed and free preserve their roles.

fitness means the selected loss, not necessarily likelihood. converged reports the optimizer’s stopping criterion. It does not establish parameter recovery, a global optimum or an adequate account of the behavior.

10.4 What the template adds

A FitResult is not a complete experiment specification. The fitting template saves additional fields for the observation source and selection, model factory, component creators, loss, package version, numerical precision, source fingerprint and run settings. It also saves the objective recalculated from the returned parameters. These are project conventions added around the fitter’s result.

Data Simulation consumes the returned parameter values with an explicit assignment to participant IDs. Applying pooled values to participants requires that assignment; the -1 label is not a participant in the observation dataset. Model Evaluation uses the objective and provenance to establish which comparisons are appropriate.

The fitting template supplies the complete configuration, optimization, saving, objective recalculation and subsequent simulation. This guide explains the interfaces that procedure connects.

The supplied CMR fit estimates nine continuous parameters with learning before context updating and repeated recalls disabled. Preparation compared seeds 0 and 1, each with three restarts; search_comparison retains both results and the selected seed. These are preparation metadata, not required FitResult fields. The source fingerprint identifies the actual code even when a version label is unchanged. Historical parameters require their original model semantics; loading them into a changed implementation does not reproduce the original fit.

DE’s pop_size multiplies the number of free parameters. MapEvosaxDE’s map_batch_size controls participant batching when pooled=False; subject_indices still selects the work unit. Gradient fitters require a differentiable objective; the template’s likelihood is suitable. Their screening and restart controls replace DE’s population controls. To exercise only fitting, set redo_sims=False and redo_figures=False. One entry in model_configs makes a single-model job.
