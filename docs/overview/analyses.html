Recall Analyses

  • Show All Code
  • Hide All Code

Recall analyses connect response data to numerical summaries and figures. JAXCMR exposes several interfaces for this work. The appropriate entry point depends on whether a function receives recall arrays, a dataset, or model simulations to compare with observations.

The analysis API reference groups the operations by measure. Statistical summaries report finite participant means and paired comparisons; they do not calculate the underlying recall scores.

Item recall probabilities credit all presentations of a recalled item, once per trial. For presentations [7, 2, 7], response code 1 or 3 recalls item 7; its presentation-based recall rate is 2/3. Duplicate responses do not add hits. Padding and positions beyond listLength are excluded. This rule applies to SPC, category recall, factor analyses and co-recall, where pairs of occurrences of the same item are excluded. Serial-accuracy and transition procedures retain their own ordering and eligibility rules.

Paired comparisons use the same finite participant pairs for their means and tests. Their DataFrames contain unrounded, two-sided t and Wilcoxon results, without a multiple-comparison correction. Arrange participant rows in the same order before comparing them. Plot intervals use finite participant scores and BCa resampling; n_resamples and bootstrap_seed control repeatability.

RPL spacing bins are explicit inclusive ranges in intervening-item units. Counts are pooled within each participant before calculating a bin probability; the once-presented-item column stays separate. Slope coordinates must be supplied explicitly and exclude that column.

The analysis interfaces

Interface Example Input → output
Array calculation fixed_pres_spc() Recall array and list length → values by study position.
Dataset analysis spc() A selected dataset → values by study position, accounting for repeated study items.
Participant aggregation apply_by_subject() Dataset, mask and dataset-analysis function → one result per selected participant.
Plotting plot_spc() Dataset(s) and mask(s) → a Matplotlib Axes, with participant summaries and intervals.
Objective callback RecallAnalysisFn Selected observed or simulated recalls and metadata → a comparable numerical summary.

Functions in jaxcmr.analyses have task-specific arguments. Read their signatures when choosing an analysis; array calculations, dataset functions and objective callbacks have different responsibilities.

Adding a summary to a model objective

A behavioral MSE loss applies the same analysis to observed and simulated recall. A function that accepts a recall dataset and returns a fixed-shape array can serve as its summary.

The RecallAnalysisFn protocol in jaxcmr.loss.mse describes this callback.

def summary(dataset: RecallDataset, /) -> Array: ...

The loss passes the selected trial rows to the analysis. For predictions, each simulation has its own row with the corresponding study list and metadata. Both datasets record recalls as study positions.

The analysis determines how trials and participants contribute to the summary. It must support JAX tracing and return the same shape for observations and predictions. A nonfinite observed bin is excluded from the loss. A nonfinite prediction for a usable observed bin gives infinite loss.

Selecting and summarizing trials

generate_trial_mask() returns a one-dimensional Boolean mask; it does not filter the dictionary itself. A dataset-based analysis receives the selected rows of every field. apply_by_subject() performs that selection separately for each participant and passes each selected dictionary to its function.

0 — Locate the project inputs 
from pathlib import Path

from jaxcmr.helpers import find_project_root, resolve_project_path

try:
    root_path = find_project_root()
except FileNotFoundError:
    root_path = Path.cwd()
Select mixed lists and compare the analysis input/output shapes 
import jax.numpy as jnp
from jaxcmr.helpers import load_data
from jaxcmr.dataset import generate_trial_mask, apply_by_subject
from jaxcmr.analyses.spc import spc, plot_spc

data = load_data(resolve_project_path("data/Dupertuys2026.h5", root_path))
mixed = generate_trial_mask(data, "data['list_type'] == 1")
selected = {name: values[mixed] for name, values in data.items()}
pooled = spc(selected)
per_subject = jnp.stack(apply_by_subject(data, mixed, spc))
print("Selected trials:", int(mixed.sum()))
print("Pooled summary shape:", pooled.shape)
print("Participant summary shape:", per_subject.shape)
Selected trials: 246
Pooled summary shape: (12,)
Participant summary shape: (123, 12)

The selection contains 246 complete twelve-item lists without repeated items.

spc(selected) pools trials. apply_by_subject() returns a list of results in ascending participant-ID order, omitting participants with no selected trials. It returns no ID column; retain the corresponding selected IDs when needed. Averaging these results weights participants equally. With unequal numbers of lists, that differs from pooling all trials.

plot_spc() performs participant aggregation and creates its own axes when none are supplied. It returns those axes for further customization.

Use JAXCMR to plot participant-aggregated recall 
plot_spc(data, mixed, labels=["Mixed lists"]);

Using SPC as the loss summary

spc already accepts a dataset and returns one recall probability per study position. Passing it to the loss gives observed and simulated recalls the same rules for repeated items, pooling trials, and excluding padding.

Use the dataset SPC as the MSE summary 
from jaxcmr.loss.mse import make_factory as make_summary_loss

SpcLoss = make_summary_loss({"spc": spc}, simulation_count=2)
spc(selected)

Measurements and recall status

A factor here is a numeric measurement attached to each presentation, such as LPP amplitude. Its array and the category array align with the study slots in pres_itemnos (see Data). Choose the analysis by what you want to summarize:

Function Result within each category
cat_factor_spc Mean measurement at each study position; does not use recalls.
cat_factor_by_recall Mean measurement at each position, with rows [recalled, not recalled].
cat_recall_by_factor Recall probability within measurement bins; use common bin edges for comparisons.

These functions pool eligible observations. Their subject_... counterparts return a leading participant axis; averaging available participant results weights participants equally. The plotting wrappers use that equal weighting. Padding, positions beyond listLength, nonfinite measurements and failed quality flags are excluded from averages or bin counts. Empty groups are NaN. When supplied, valid_field names finite, positive flags for included observations.

For repeated items, position-based and item-based recall classification differ:

For presentations [7, 2, 7, 0], length 3, recalls [1, 1, 0] Position 1 Position 2 Position 3 Padding
Default position-based classification Recalled Not recalled Not recalled Excluded
expand_repetitions=True Recalled Not recalled Recalled Excluded

cat_factor_by_recall and the LPP recall-status plot default to position-based classification. Simulation reports first-occurrence positions, so a later presentation can be labelled “Not recalled” even though its item was recalled. Expansion applies the item’s status to every valid occurrence; it does not identify which presentation caused remembering. The plot labels stay “Recalled” and “Not recalled” in both modes. cat_recall_by_factor uses direct positions and has no expansion option. Duplicate responses count once in these analyses.

Measurement availability stays separate from recall classification. Here the first occurrence’s measurement is missing and fails quality screening, but the item was recalled. Expansion still puts its third-position measurement in the recalled group:

import jax.numpy as jnp
from jaxcmr.analyses.factors import cat_factor_by_recall

example = {
    "subject": jnp.array([[1]]),
    "listLength": jnp.array([[3]]),
    "pres_itemnos": jnp.array([[7, 2, 7, 0]]),
    "recalls": jnp.array([[1, 1, 0]]),
    "category": jnp.array([[1, 1, 1, 0]]),
    "LateLPP": jnp.array([[jnp.nan, 4., 6., jnp.nan]]),
    "quality": jnp.array([[0, 1, 1, 0]]),
}
means = cat_factor_by_recall(
    example, "category", 1, "LateLPP",
    valid_field="quality", expand_repetitions=True,
)
# Rows: recalled, not recalled; columns: the four stored study positions.
# [[nan, nan, 6., nan],
#  [nan, 4., nan, nan]]

Template input conventions

Input or setting Interpretation
Distance matrix Square array indexed by global item identifier minus one; use the same matrix and bins for comparisons.
Distance-CRP features_path Item-by-feature array, using the same identifier alignment; takes precedence over the precomputed matrix.
Category-CRP category_features_path One category per item, or an item-by-feature array with zero-based feature_column; otherwise derive categories from the dataset.
Category recall comparisons (label, left_condition, left_category, right_condition, right_category); indices are zero-based positions in the configured conditions and category_values.
contrast_of_contrasts (label, left_a, left_b, right_a, right_b) with each cell expressed as (condition_index, category_index).

Category contrasts pair the participant IDs with defined values in every required cell. Missing cells remain unavailable, not zero. Category denominators exclude padded study slots. PNR divides by selected trials, including trials that end before the queried response. Conditional stopping uses the sequences still at risk; the terminal recording bin need not be an observed stop. The supplied simulations impose recorded recall counts, so matching lengths and pure-list category totals are not predictions.

Temporal and semantic transition measures compare actual transitions with eligible unrecalled alternatives. Their undefined bins remain undefined. Rank summaries and their statistical output use the configured participant-level scores; simulation repetitions retain their participant identifiers. The template’s rank method and uncertainty settings determine the reference and interval calculation.

Numerical analyses assume aligned trial and study-position arrays. Field names, array shapes and item-code conventions are input requirements, not exhaustive runtime checks. Category and factor fields must match pres_itemnos; recalls and list lengths must share its trial rows. These contracts apply in ordinary calls as well as JAX transformations.

Global item-distance requirements

Supply pres_itemids as an aligned integer array of global item identities. ID i selects row and column i - 1 of a square numeric distance matrix; zero pads unused study positions. All selected positive IDs must be within the matrix vocabulary and identify the same items in every dataset.

Distances between distinct valid study positions must be finite. Repeated identities at different positions require a finite matrix diagonal entry for that pair. Unused vocabulary entries and each position’s self-distance may be missing. You are responsible for these requirements, the scientific item mapping, and the choice and scale of distances. JAXCMR does not validate them.

from jaxcmr.analyses.distrank import subject_distrank

selected = data["list_type"].ravel() == 1
scores = subject_distrank(data, selected, distances)

Trial masks must be one-dimensional Boolean arrays with one entry per trial; integer row-index arrays are not masks. Numerical functions such as distrank and dist_crp remain directly usable with jax.jit; their callers must supply aligned integer IDs within matrix coverage. The temporal CRP and rank templates retain their complete-study-list safeguard; these estimators have not been extended to incomplete lists.

Arranging comparisons and saving figures

comparison_panels arranges already-selected datasets for plotting. The caller chooses whether each panel compares conditions within one dataset or compares datasets within each condition. The choice stays explicit even with one file.

import matplotlib.pyplot as plt
from jaxcmr.dataset import select_conditions
from jaxcmr.plotting import comparison_panels
from jaxcmr.analyses.spc import plot_spc

datasets = [observed, simulated]  # Already loaded by your script.
queries = ["data['list_type'] == 1", "data['list_type'] == 2"]
masks = [[s.mask for s in select_conditions(d, queries)] for d in datasets]
panels = comparison_panels(
    datasets, masks, ["Observed", "Model"], ["Condition 1", "Condition 2"],
    mode="datasets",
)
for panel in panels:
    figure, axis = plt.subplots()
    plot_spc(panel["datasets"], panel["trial_masks"], labels=panel["labels"], axis=axis)
    axis.set_title(panel["title"])

With mode="conditions", supply one dataset: its conditions become the curves in one panel, titled by selection_label. With mode="datasets", conditions become panels and datasets become curves. Each returned dictionary contains datasets, trial_masks, labels, and title; no data are loaded or plotted. Dataset, label and condition counts must correspond; supply masks with the annotated shapes. Callers can extend these dictionaries for category or output-position comparisons, as the templates do.

For a sequence of behavioral analyses, iter_analysis_figures handles the common plotting loop without taking over input loading or saving:

from jaxcmr.plotting import iter_analysis_figures
from jaxcmr.plotting import save_figure

analyses = [
    {"target": plot_spc, "title": "Serial position", "figure_suffix": "spc"},
    {"target": "jaxcmr.analyses.crp.plot_crp", "title": "Lag transitions"},
]
for figure, suffix in iter_analysis_figures(
    [observed, simulated], analyses, ["Observed", "Model"],
    base_masks=[selected_observations, None],
):
    save_figure(str(output_folder), "comparison", suffix=suffix, figure=figure)
    plt.close(figure)

Each target can be a callable or an import path. An analysis’s trial_query overrides the default query and is intersected with each dataset’s explicit base mask; None base masks select all trials. Configuration entries can set labels, contrast names, figure dimensions, titles, limits, and additional plot kwargs. Those kwargs override default plot options; an explicit color_cycle overrides the corresponding keyword. Configurations run in order, yielding one figure at a time. Suffixes use figure_suffix or the target name without plot_, followed by the supplied common suffix. Repeated targets without their own suffix also append their one-based configuration position. The iterator neither loads nor saves files. save_figure(..., figure=figure) saves the specified figure even if another one is current, while retaining its existing display behavior. Without that argument, it continues to save the current figure.
