Local setup with VS Code

Use VS Code to write and run Python notebooks, work with your own files, and save results for later. This guide creates your own research project and installs JAXCMR into its Python environment. You can download tutorials and templates to use in that project; cloning the library is optional. No previous experience with Python or VS Code is assumed.

These instructions cover Macs with an Apple chip, such as an M1 or M2, and Windows PCs with a 64-bit Intel or AMD processor. Intel Macs are not supported by this installation route because the required version of JAX does not provide an Intel Mac installer. You will need an internet connection and permission to install software.

If your computer cannot use this route, you can run the code on another computer instead. The Google Colab setup guide prepares a notebook workspace in your browser using Google’s computers. If you have access to a research cluster, follow Slurm cluster setup with VS Code to prepare it for JAXCMR. Both routes run Python on the remote computer.

On a Mac, choose Apple menu → About This Mac to check: an Apple chip is listed under Chip; an Intel processor is listed under Processor.

The screenshots use dark mode; the same controls are available in light mode. Red boxes mark the controls to look for. The VS Code images show Microsoft examples, so use the JAXCMR filenames and Python version specified in the steps below.

1. Install VS Code

Visual Studio Code, usually called VS Code, is the application you will use to open project files and work with notebooks.

A Jupyter notebook is a file ending in .ipynb that combines explanations, Python code, and results. Its sections are called cells. Text cells explain the work; code cells contain instructions for Python to execute. The Jupyter extension below gives VS Code its notebook controls.

Download the version for your computer:

  • Mac: choose the Apple Silicon download. Open the downloaded ZIP file if needed, then move Visual Studio Code to your Applications folder.
  • Windows: choose the x64 User Installer, open it, and follow the installation steps.

Open VS Code. You will also need two extensions: additions that let VS Code work with Python and the example files used in this guide.

  1. Choose View → Extensions.
  2. Search for Python. Select the extension published by Microsoft and click Install.
  3. Search for Jupyter. Select the extension published by Microsoft and click Install.

2. Install Git

The installation command below uses Git to fetch JAXCMR from GitHub, the website where its source is stored. You do not need a GitHub account or a separate checkout of JAXCMR’s repository.

Some of the steps below use a terminal: a panel where you give your computer instructions by typing commands. In VS Code, choose Terminal → New Terminal to open it. To run a command, copy it into the terminal and press Return on Mac or Enter on Windows. Do not copy the surrounding box or add any extra characters.

  • Mac
  • Windows

In the VS Code terminal, run:

xcode-select --install

Follow the prompts to install Apple’s Command Line Tools, which include Git. If you see a message saying the tools are already installed, continue to the next step.

Download the x64 installer from Git for Windows and run it.

Use the default installation options. In particular, keep Git from the command line and also from 3rd-party software when asked how Git should be used.

Finish the installation before continuing.

3. Install uv

Python runs the calculations, and JAXCMR is a package of Python tools for memory research. uv installs Python and the packages this project needs, keeping them together in an environment. This lets notebooks in the project use the same installed software. You do not need to install Python separately.

In VS Code, open Terminal → New Terminal if the terminal is not already open. Run the command for your computer:

  • Mac
  • Windows
curl -LsSf https://astral.sh/uv/install.sh | sh

Use a PowerShell terminal. If the terminal has a different name, use the arrow beside the + button in the terminal panel and choose PowerShell.

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

These are the commands from uv’s installation instructions.

When installation finishes, quit VS Code completely and reopen it so it can find Git and uv. On Mac, use Code → Quit Visual Studio Code; on Windows, close all VS Code windows.

Open Terminal → New Terminal and run these commands one at a time:

git --version
uv --version

Each should print its name and a version number, such as git version … and uv …. If either command is not found or not recognized, see If something goes wrong before continuing.

4. Create your project folder

A project folder keeps the notebooks, inputs, results, and software settings for one piece of research together.

Using Finder or Windows File Explorer, create a folder somewhere convenient, such as Documents. Give it a meaningful name; this guide uses memory-project.

In VS Code, choose File → Open Folder and open that folder. If prompted, confirm that you trust the folder you created.

Choose View → Explorer to see the folder in the left-hand panel. Right-click its name and choose New Folder to create each of these three folders:

memory-project/
├── notebooks/
├── data/
└── results/

Keep your notebooks in notebooks, input files in data, and saved outputs in results. These names are suggestions; you can use another arrangement or keep large datasets elsewhere.

5. Install Python and JAXCMR for this project

Choose Terminal → New Terminal. The terminal should open inside memory-project.

If you already have a uv-managed research project, open that folder and run only the uv add command below; keep its existing project configuration. For a new project, run all three commands one at a time:

uv init --bare --python 3.12 --vcs none
uv python pin 3.12
uv add "jaxcmr @ git+https://github.com/githubpsyche/jaxcmr.git@main" ipykernel pandas

The first command creates the project’s software configuration. --bare keeps the starting files minimal, and --vcs none leaves version-control setup to you. The second records Python 3.12 as the version to use. See uv’s project commands.

The last command installs:

  • JAXCMR, from the GitHub version used by this documentation.
  • ipykernel, which lets VS Code run notebook cells using this environment.
  • pandas, which provides the table-reading and writing tools used later in this guide.

uv downloads Python if needed and installs the packages in a .venv folder inside your project. Wait for installation to finish successfully before continuing. uv’s VS Code instructions explain the notebook connection.

After installation, your folder also contains:

File or folder Purpose
pyproject.toml Records the packages your project uses.
uv.lock Records the resolved package versions and JAXCMR revision.
.python-version Records the Python version to use.
.venv Contains the installed software for this computer.

Keep the three configuration files with your research project. They let uv recreate its environment on another computer. See uv’s project structure.

6. Create or download a notebook

With memory-project open in VS Code, choose how to begin:

  • Create your own notebook: open View → Command Palette, which searches VS Code’s commands, run Create: New Jupyter Notebook, and use File → Save As to save it in notebooks with a filename ending in .ipynb.
  • Use a JAXCMR tutorial or template: open its documentation page and choose Download notebook. Move the downloaded file into notebooks, then open it in VS Code.
  • Continue existing work: open its notebook from Explorer.

Choose Select Kernel → Select Another Kernel → Python Environments and select the Python 3.12 .venv inside your memory-project folder. If Python Environments is already shown, choose it directly. A kernel is the running Python process; the selected environment supplies its installed packages. Use that environment for each notebook belonging to this project. If a kernel is already selected, click its name to check or change it.

Downloading a notebook and its inputs

A notebook download contains its code, explanations, and saved cell outputs. Separate input files must also be available.

The data-preparation tutorial creates its small teaching dataset in code. Other notebooks may need downloaded inputs: the templates page lists the example files and where to save them.

The templates’ automatic example downloads currently run in Colab. For local work, download the required files yourself or supply your own data.

When a notebook has a project_root setting, set it to the full path of memory-project. In Explorer, right-click that folder and choose Copy Path. For example:

project_root = r"PASTE_PROJECT_PATH_HERE"

Replace the text between the quotation marks. This makes the notebook’s relative input and output paths refer to your project folder, even though the notebook itself is saved inside notebooks.

Check its input and output settings before running. If it has a notebook_source setting, update that to your saved notebook’s location so its record of the run includes your copy. The next section explains file paths in more detail.

Work with cells

Use + Code to add Python instructions and + Markdown to add explanatory text. Click inside a code cell to edit it. Run it with the triangle beside the cell or Shift+Enter; its output appears underneath. Run All executes the notebook from top to bottom. See VS Code’s notebook controls.

Cells use values created by earlier executions. Changing a value in an earlier cell requires running that cell again, followed by the cells that depend on it. Editing code alone does not update the results.

Arrange your notebook so it can run in order: imports and settings, loading files, calculations, then saving results. Stop and resolve an error before running cells that depend on the failed step.

7. Use your own files

Copy your input files into the project’s data folder using Finder or Windows File Explorer, or leave them in an existing location and use their full paths.

A path identifies a file or folder. A full path starts from your computer’s filesystem root or drive. A relative path, such as data/trials.csv, is interpreted from Python’s current working folder. That folder can differ from the terminal’s; inspect it inside the notebook with:

from pathlib import Path

print(Path.cwd())

For a straightforward starting arrangement, use a full project path. In VS Code’s Explorer, right-click memory-project and choose Copy Path. Paste it between the quotation marks below, replacing PASTE_PROJECT_PATH_HERE:

project = Path(r"PASTE_PROJECT_PATH_HERE")
input_path = project / "data" / "trials.csv"
output_dir = project / "results"
output_dir.mkdir(parents=True, exist_ok=True)

print("Input file exists:", input_path.is_file())
print("Save results in:", output_dir)

Keep the r before the quotation mark; it allows Windows paths containing backslashes. Replace trials.csv with your filename. / joins path components, and mkdir creates the output folder if needed. If the input check prints False, compare the path with the file’s actual location and spelling. These operations use Python’s path tools.

For a CSV table, load and inspect it with:

import pandas as pd

table = pd.read_csv(input_path)
table.head()

pandas is installed with this workspace. The import makes its tools available as pd; table holds the loaded data in Python’s memory, and head() displays its first few rows. Other file formats need a suitable reader. See pandas’ CSV reader.

When adapting a JAXCMR template, edit its existing configuration cell: set project_root to your project’s full path and adjust its input and output settings. Check additional locations such as simulation_dir or figure_dir where present. Moving a notebook does not automatically change the files it reads or writes.

Preparing data for JAXCMR explains the data format needed for modelling.

8. Save results and return later

File → Save preserves the notebook’s code, explanations, and displayed outputs. To use a result in another notebook or application, write it as a separate file.

For example, save the table loaded above as a CSV:

saved_path = output_dir / "trials-copy.csv"
table.to_csv(saved_path, index=False)
print(saved_path)

index=False leaves out pandas’ extra row-number column. After an analysis, use this pattern with its result table and a meaningful filename. Choose distinct filenames or folders for results you want to retain separately; saving to an existing filename can replace it. See pandas’ CSV writer.

Find the saved file in Explorer. A figure needs its own save operation; JAXCMR templates save files according to their output settings.

Closing VS Code leaves your saved files and installed environment on disk. A new or restarted kernel begins without the previous session’s Python variables. Restart Kernel clears that running state without removing installed packages. Results already visible in a notebook may be saved output from an earlier session.

When returning:

  1. Use File → Open Folder to open memory-project, then open your notebook.
  2. Select the project’s .venv.
  3. Run the imports and path settings.
  4. Load your inputs or previously saved results, then run the calculations you need.

For example, after defining project and importing pandas, a later notebook can read the saved table:

saved_table = pd.read_csv(project / "results" / "trials-copy.csv")

Saved files let separate notebooks share results. Using the same environment gives them access to the same packages; it does not automatically share their variables. You normally do not repeat installation for each notebook.

Use Run All when you intend to repeat the whole workflow. To continue from saved results, load those files and run the subsequent steps.

Add software or move to another computer

You normally install packages once per project. If another notebook needs an additional package, add it from a terminal in this folder using uv add PACKAGE_NAME, replacing the placeholder with that package’s name. This records the dependency as well as installing it. See Managing project dependencies.

On another computer, copy pyproject.toml, uv.lock, and .python-version along with the notebooks and data you need. Install Git and uv there, open the copied project folder, and recreate the environment with:

uv sync --locked

Recreate .venv on the destination computer rather than copying it. Keep backups of your notebooks, inputs, results, and configuration files.

NoteOptional: check your installation

Download the first simulation notebook, move it into notebooks, and open it in VS Code. Select the Python 3.12 .venv inside your memory-project folder. This supplied notebook needs no input file.

Click Run All at the top of the notebook. This runs its code cells in order, so later cells can use what earlier cells have prepared. The first cell is for Colab and skips installation on your computer.

You may already see saved results when you open the file; they do not mean its code has run in your current session. Run All computes them again. Wait for execution to finish; the first run may take longer while JAX prepares the calculation. If a cell reports an error, resolve it before continuing.

The last code cell prints:

Study order: [1 2 3 4 5]
Simulated recalls: [1 5 2 4 3]

Reaching this output confirms that the selected Python environment can load JAXCMR and execute a model. The notebook’s Read the output section explains the simulation.

Completing this check verifies installation; use the earlier sections to work with your own notebooks and files.

NoteOptional: get the complete JAXCMR repository

JAXCMR’s repository contains its source code, examples, and documentation. Cloning downloads a checkout of that collection. Use this route if you want to work on the library itself or obtain the complete examples. The existing template tour, which coordinates several notebooks and supplied datasets, currently uses this route.

Keep the checkout in a separate folder beside your research project. In VS Code, open the parent folder, such as Documents, choose Terminal → New Terminal, and run:

git clone https://github.com/githubpsyche/jaxcmr.git
cd jaxcmr
uv sync --locked

The first command downloads the repository into a new jaxcmr folder, cd moves the terminal into it, and uv sync --locked installs its recorded software environment.

Open the resulting jaxcmr folder with File → Open Folder, confirm trust if prompted, and select its .venv when working through repository examples or modifying the library. Return to your research folder and its environment for your own project.

If something goes wrong

Git or uv is not found

Quit VS Code completely, reopen it, and open a new terminal. Try git --version and uv --version again. If a command is still missing, check that its installation finished successfully.

uv cannot find pyproject.toml

The terminal is probably in the wrong folder. Use File → Open Folder to open your research folder containing pyproject.toml, then open a new terminal and retry the command. For a new folder without that file, complete step 5 first.

.venv is not listed as a kernel

Check that the uv add installation in step 5, or uv sync --locked for a copied project, finished successfully. Quit and reopen VS Code, reopen the notebook, and try the kernel picker again.

The notebook says No module named jaxcmr

Check that installation finished in your research project folder and that the notebook’s selected kernel uses the .venv inside that folder. Select that environment, then rerun the cell that imports JAXCMR.

A name is not defined

Run the earlier cell that defines that name, including imports and path settings. Variables from a previous kernel session or a different notebook are not automatically available.

A file is not found

Compare the filename and location with Copy Path in Explorer. Check Path.cwd() if using a relative path. Moving or copying a notebook does not move its input files or update its path settings.

JAX reports a DLL error on Windows

JAX may also need Microsoft’s Visual C++ Redistributable for x64. Install it, restart VS Code, and try running the notebook again. This requirement is described in JAX’s installation instructions.

If you ask for help, include the step you reached and the complete error message.
