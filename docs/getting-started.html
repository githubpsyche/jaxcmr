2  Run JAXCMR in VS Code

By the end of this page, you will have a folder for your work, a Python environment with JAXCMR installed, and a notebook that can run Python code. You do not need previous Python experience or a research dataset.

For browser-based execution, follow the Colab instructions instead. That route installs the library inside a hosted notebook.

These instructions are for an Apple Silicon Mac (M1 or newer) with an internet connection. You can find your Mac’s chip under Apple menu → About This Mac. Allow time for the initial downloads.

NoteRelease status

This page targets JAXCMR 0.2.0, which is not yet available on PyPI. The installation command below needs that release. Publication and confirmation of these steps in a fresh environment are still required before this local setup is ready to use.

2.1 1. Install the editor

Download Visual Studio Code for Mac, open the download, drag the app into Applications, and launch it.

Open Extensions from the left sidebar, or press Shift–Command–X. Install Python and Jupyter, both published by Microsoft. These extensions let VS Code edit and run Python notebooks.

2.2 2. Create a working folder

In Finder, open Documents and create a folder named jaxcmr-workshop. In VS Code, choose File → Open Folder… and open that folder. If VS Code asks whether you trust this folder, confirm for the folder you just created.

Choose Terminal → New Terminal. The terminal is the panel where you enter installation commands. Later, you will enter Python code into a notebook cell; the terminal and the notebook are separate places to enter code.

2.3 3. Install Python and packages

Run these commands in the terminal one at a time. Press Return after each command and wait until the prompt reappears before continuing:

curl -LsSf https://astral.sh/uv/install.sh | env UV_UNMANAGED_INSTALL="$PWD/.tools" sh
.tools/uv venv --python 3.12 --managed-python --seed .venv
.venv/bin/python -m pip install "jaxcmr==0.2.0" "ipykernel>=6.29.5"

The first command downloads uv, which can install Python for you. The second creates a Python 3.12 environment in this folder’s .venv directory. An environment keeps the Python and packages for this work together. The third installs JAXCMR and the package that runs Python inside a notebook.

The commands name this environment directly, so you do not need an activation command or an existing Python installation. The first downloads can take several minutes. See uv’s installer options and Python installation guide for details.

2.4 4. Create a notebook and select its environment

Press Shift–Command–P to open VS Code’s Command Palette. Choose Create: New Jupyter Notebook. Save the new notebook as setup-check.ipynb inside your jaxcmr-workshop folder.

Click Select Kernel at the upper right of the notebook. If a kernel is already selected, click its name and choose Select Another Kernel…. Choose Python Environments…, then the Python 3.12 environment whose location ends in jaxcmr-workshop/.venv/bin/python.

A kernel is the Python process that runs the notebook’s cells. Selecting this kernel tells the notebook to use the environment where you installed JAXCMR. See the VS Code notebook guide and kernel selection instructions.

2.5 5. Run the setup cell

Paste this code into the notebook’s first code cell, then click the triangle beside the cell to run it:

import sys
import jax.numpy as jnp
import jaxcmr

print("Python:", sys.version.split()[0])
print("Environment:", sys.executable)
print("JAXCMR:", jaxcmr.__version__)
print("JAX calculation:", int(jnp.arange(4).sum()))

You should see four lines like these:

Python: 3.12.…
Environment: /Users/your-name/Documents/jaxcmr-workshop/.venv/bin/python
JAXCMR: 0.2.0
JAX calculation: 6

Your Python patch version and username will differ. The environment path should point inside your working folder’s .venv, the JAXCMR version should be 0.2.0, and the calculation should give 6. The calculation adds the numbers 0, 1, 2 and 3 using JAX.

This establishes that your notebook can use the installed packages. No model or dataset is needed for this step.

2.6 6. Save and return later

Save the notebook with Command–S. When you return, open the same folder and notebook in VS Code and select the same .venv kernel.

Use Restart Kernel, then Run All, to run the notebook in a fresh Python session. You should see the same four results. Saved output records an earlier run; restarting the kernel clears its working memory, so cells need to run again before later cells can use their results.

2.7 If a step fails

What you see What to do
.tools/uv or .venv/bin/python cannot be found Check that VS Code has your jaxcmr-workshop folder open. Open a new terminal there and complete step 3 in order.
.venv is missing from the kernel list Confirm step 3 finished successfully. Close and reopen the folder, then select the notebook kernel again.
VS Code asks to install ipykernel Re-run the final command in step 3, then select this folder’s .venv kernel.
ModuleNotFoundError: No module named 'jaxcmr' Check the selected kernel’s path. Select this folder’s .venv and, if necessary, re-run the final installation command.
The printed JAXCMR version is not 0.2.0 Check the environment path and reselect the correct kernel. Re-run the pinned installation command after confirming that the release is available.
pip cannot find jaxcmr==0.2.0 Check the release-status note above. This setup cannot be completed until that version is available; do not substitute an older version.

If an error remains, keep its text and any setup-cell output so the person helping you can identify the environment and the failing step.

2.8 Continue with fitting

Once the setup cell runs successfully, start with Fitting models. It brings together parameter estimation, simulation and behavioral analyses, ending with saved results and figures comparing model predictions with observations.

Follow From a template to a run to place the notebook and its inputs in your working folder and use the environment you have just created. The notebook’s saved example shows the complete procedure; its parameters cell configures the run you execute.
