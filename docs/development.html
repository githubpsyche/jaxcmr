Contributing to JAXCMR

The Python source lives in jaxcmr/ and the tests in tests/. If you’re editing something readers see on the website, your starting point might be a Python docstring, a guide page, or a template notebook.

Set up a checkout

A checkout is your local copy of the repository. Open a terminal in its top-level folder, the one containing pyproject.toml and uv.lock. If you still need a copy, follow the checkout instructions. Run the commands on this page from that folder.

uv sync --locked --extra test --group reader --group docs

uv sync prepares a Python environment in .venv and installs JAXCMR from your checkout. The next time you start Python in that environment, it uses your edited source. Syncing can remove packages outside the selection from an existing environment.

  • --locked uses the package versions recorded in uv.lock. If the lockfile needs updating, uv stops and tells you.
  • --extra test includes pytest, the program that runs the library tests.
  • --group reader adds tools for running and checking notebooks.
  • --group docs adds the Python tools for generating the API reference. To render web pages, also install Quarto 1.11.9.

Change and test the library

The serial position curve answers a question about each study position. What fraction of the items presented there were recalled? The calculation is spc in jaxcmr/analyses/spc.py. Its tests are in tests/test_recall_measures.py. Run them once before editing so you know which checks already pass.

uv run --no-sync python -m pytest tests/test_recall_measures.py

uv run --no-sync uses the environment you just prepared and skips the installation step. python -m pytest starts pytest with that environment’s Python. The path selects one test file. At the end, pytest reports how many tests passed or failed. For a failure, it shows the test name and the comparison that failed.

Give your change a test whose expected result you can work out by hand. Suppose the study lists are [A, B, A] and [C, D]. The participant recalls A twice on the first trial and nothing on the second. Each position where A was studied gets credit once. The recall fractions for positions 1, 2, and 3 are 1/2, 0/2, and 1/1. Only the first list contributes to the third denominator. In the test file, look for test_position_codes_recall_all_presentations_without_double_counting to see how a similar list and its expected scores are written in Python. Run the same test command after editing the function and its test.

If you change how the experimental CMR fitters prepare observations, run uv run --no-sync python -m pytest -m audit. Here -m audit selects the tests that check whether JAX can reuse a compiled calculation when the selected trials change.

Edit notebooks and documentation

Change a notebook

To change the category recall rate template, open templates/cat_recall_rate.ipynb. Tutorial and Library Guide notebooks live in guide/tutorials/ and guide/overview/. If you change a calculation, select the checkout’s Python environment as the notebook kernel, run the cells, and save the output you want readers to see. For a text-only edit, the existing output can stay.

You can then test the saved template from the terminal.

uv run --no-sync python guide/tools/check_notebooks.py --select cat_recall_rate

The script runs a temporary copy with a small workload and checks its results. Your original keeps the settings and output you saved. The script prints the path to a report showing which notebooks passed. --select picks one notebook by its name, such as cat_recall_rate. Omit it to run the whole collection.

Change an API reference entry

Suppose you’re clarifying the entry for simulate_dataset. Edit the description inside that function in jaxcmr/simulation.py (its docstring). The docstring at the top of the module supplies the page introduction. To add an entry or move it under a different heading, edit the list in guide/reference/_simulation.yml.

quarto render guide/reference/simulation.qmd

This rebuilds the simulation reference page. Open docs/reference/simulation.html and follow the function’s link in the summary table to check the description a reader will see.

Change an input supplied with the package

If a notebook uses one of JAXCMR’s bundled datasets or saved fits, edit the source file under data/. For a new file, also add its path to _EXAMPLE_FILES in jaxcmr/examples.py, so copy_example_inputs recognizes it, and to the wheel and source-archive file lists in pyproject.toml, so it ships with the package.

Add --reinstall-package jaxcmr to the setup command above to refresh the installed copy of the data. Rerun the notebook that reads it. To check that someone installing the package also receives the file, run uv run --no-sync python -m pytest tests/test_distribution.py. These tests build and install the package in a fresh environment and need internet access for dependencies.

Preview and share your change

Build a local copy of the website to review a change to the guide or templates.

bash build-docs.sh
uv run --no-sync python guide/tools/check_site.py docs

The first command builds the site in docs/ using the outputs already saved in the notebooks. The second checks local links, notebook downloads, and example files. Open docs/index.html and follow the link to the page you changed. To inspect a revised notebook, use its download link. Open in Colab opens the version on GitHub’s main branch.

To propose a code or documentation change, open a pull request asking to merge the edits on your branch into JAXCMR. If you’re working in your own copy on GitHub, follow GitHub’s instructions for submitting from a fork. Describe what will change for readers or researchers and how you checked it. GitHub runs the routine library tests on Linux, macOS, and Windows and checks the website build. The notebook runner and the clean-install tests run locally, so include their results if you ran them.
