27  Development

For changes to JAXCMR itself, start with Developer Setup to obtain the checkout and environment. Run the commands below from the repository root.

27.1 Run the tests

Install the test dependencies alongside the default development tools, then run the complete suite:

uv sync --locked --extra test
uv run --no-sync python -m pytest

While editing, run the relevant test file:

uv run --no-sync python -m pytest tests/test_transitions.py

The complete run includes scientific regressions, package installation and notebook execution checks. Installation checks require internet access and create temporary environments. Run the full suite before submitting changes. The CI workflow defines the supported check platforms.

The historical test-suite audit records the earlier suite consolidation.

27.2 Add or change a test

  • Each new scenario must catch an incorrect behavior that existing scenarios do not.
  • Prefer independently established numerical answers and supported workflows over checks of shapes or types alone.
  • Keep expected answers beside their scenarios. Share fixtures where they reduce duplication; see the fixture documentation.
  • Expose independent scenarios through parametrization instead of hiding them in loops.
  • Required checks must not silently skip because private data is missing.

27.3 Edit the documentation

Edit the sources; the build prepares notebook copies, downloads and HTML:

Material Authoritative location
Published templates templates/
Book pages and supporting examples guide/
Generated notebook copies and downloads guide/templates/, guide/downloads/
Rendered website docs/

guide/_quarto.yml selects the published chapters. Install Quarto 1.10.20 or newer, then render the book:

bash build-docs.sh

This command prepares notebook chapters before Quarto checks that they exist, so it also works in a fresh checkout. It refreshes downloads, removes retired staging files and clears the generated book output without executing notebook cells. Execute changed notebooks separately and retain their useful outputs before rendering. Do not edit the generated copies.

Open docs/index.html, or start a live preview:

quarto preview guide

After editing an original notebook in templates/, run bash build-docs.sh again: live preview does not watch those files outside the guide project. Review the rendered pages and notebook downloads locally before publication. Colab links and package installation follow main. GitHub Pages publishes the committed docs/ directory.
